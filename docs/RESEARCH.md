# 个人综合作品集网站 · 需求研究

版本：仓库整理版，2026-10-26。根据已完成的三步需求研究整理，后续范围变更以 [PRD](PRD.md) 为准。

## 1. 明确目标

建立以个人 IP 为核心、以真实作品为重点的中文综合作品集。集中展示项目、AI 工具、实践成果与值得分享的内容，让访问者了解网站主人是谁、关注什么、实际做过什么。

网站服务于长期积累，而不仅是电子简历。不同方向的创作可以共存，但第一版不追求栏目齐全，也不要求所有工具都能在线使用。

主要访问者包括本人、工程与技术爱好者、内容读者及潜在合作伙伴。首要任务是浏览作品、理解贡献、找到公开联系入口；不引入注册、会员、社区或私人任务管理。

希望达到的效果：

- 个人定位清楚，首页介绍简短。
- 作品有介绍、图片、个人贡献与必要的验证材料。
- 风格简约现代，白色主体，电脑与手机都能阅读。
- 新增内容方便，作品地址稳定，不必每次重写页面。
- 不编造作品、经历、链接或实验结果。

## 2. 调研类似产品

以下记录的是调研阶段的观察与借鉴结论，不表示本次重新审核了这些网站的最新页面。

| 参考 | 当时的观察 | 本项目借鉴 | 不直接照搬 |
| --- | --- | --- | --- |
| [Jamie Kang](https://jamiekang.dev/) | About、Projects、Skills 等内容清楚，作品与详情关系明确 | 简约、一目了然、导航层级浅、作品优先、统一卡片结构 | 不把网站限定成工程履历或单一技术身份 |
| [I Love Power Electronics](https://ilovepowerelectronics.com/) | 顶部栏目和 Tools 入口清楚，作品与工具共存 | 顶部导航区分主要内容，工具说明用途再提供入口 | 不要求第一版开发全部在线工具，也不强制每页有侧栏 |
| [Abdalla Elradi](https://aelradi.engineer/) | 展示项目、经历、技能和证书证明 | 成果可精选展示，必要时提供证明信息 | 不增加当前不需要的预约、服务销售和证书管理系统 |

“内容较多时使用侧边分类或筛选”是本项目形成的设计意向，不将其写成参考网站已经具备的统一布局。证书与奖项保留为后续可能性，不在没有真实材料时强制建设。

## 3. 记录发现与核心需求

### 已确认的原则

1. 综合个人 IP 定位，以项目作品为核心，同时支持工具和内容分享。
2. 白色主体、现代简洁、适量留白，不堆积首页信息。
3. 主要栏目通过顶部导航访问；手机布局可以调整导航方式。
4. 项目有稳定的独立详情地址；标题与展示排序可以更新。
5. 工具和精选分享允许暂时没有真实内容，显示诚实的简短说明。
6. 用户通过自然语言让 Codex 更新内容，不要求本人维护代码或先建设后台。

### 留待产品与开发阶段确定

- 首页精选数量、具体排序和卡片样式。
- 字体、辅助色、头像、局部动效是否采用。
- 文章是否站内承载，视频如何展示。
- 哪些工具可以公开使用，哪些仅作作品介绍。
- 证书是否启用、公开哪些证明信息。
- 部署平台、真实网址及联系入口的最终验证。

### 后续实际决策

- 首页原型确定白色主体与绿色点缀，用户要求中间留白略微收紧。
- 第一版只保留已验收的一个真实 MMC 项目，不为达到早期“3—4 个精选项目”的设想而凑数。
- 公开名称使用“双非电源仔”；小红书昵称可以复制，没有核实的主页地址则不显示跳转按钮。
- 工具与分享先保留空状态；未来新增数据可显示真实卡片。
- AI 视频等作为可扩展内容，不预设小说、书籍或视频必须独立成栏。
- 证书、复杂筛选、在线工具、完整文章系统不在本轮范围。

## 阶段结论

需求研究提供了足够的方向，可以进入 PRD。研究阶段不必解决全部页面细节，也不应反复搜集参考替代实际原型。设计偏好、确定的需求与未来设想应分开记录，避免后续误把设想当作首版必做。
